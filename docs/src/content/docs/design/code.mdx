## Functions

Functions are almost directly transpiled into a list of commands. There are some special cases, however:

### Arguments

Function arguments will be read using function macros or data locations. They will be stored in the
function's data location, which is named the same as the function's ID. They will be in the `args` object.

### Locals

Locals are stored in the same way as arguments, as arguments are technically also locals, but with a different
location in data. They will be in the `locals` object.

### Returns

Function return values will also be stored in the function's storage, in the `returns` object.

## Variables

See function locals.

## Constants, Enums, Fields

These all get skipped during codegen and references are replaced with their real values. These are purely
for syntactic sugar and ease of use.

## Conditionals

Conditionals work like this:

1. Compute the condition's result, and store it in a scoreboard value as `1` or `0`.
2. `execute if score [target] [objective] matches 1 run [...]` (if block)
3. `execute unless score [target] [objective] matches 1 run [...]` (else block)

`else if` conditions are handled in the else block and will return early if they succeed, as to not call the else block.

The blocks are converted to their own functions, which access the parent function's locals and args for references
that are carried over.

## Loops

There are three types of loops, `for [x] in [y]` loops, `for [x] in [y]..[z]`, and `while [x]`.

### Range

Here's a simple code example:

```mcfunction
# for i in 0..10

## example:loop_init

scoreboard players set index counter 0
scoreboard players set max counter 10

execute if score index counter < max counter run example:loop_run

# example:loop_run

# >> LOOP BODY HERE

scoreboard players add index counter 1
execute if score index counter < max counter run example:loop_run
```

### Iterators

The size of the array will be determined by storing it in the scoreboard. This will be used as the max value.
The elements will then be retrieved from the array using the current index in the scoreboard, like a range iterator.

### While

Pretty much just a conditional that repeatedly calls itself until the condition is false.

## Calling Conventions

Functions in DPScript compile down to regular Minecraft functions, but have a special calling convention.
Here's a code example, then we can break it down.

```mcfunction
# Calling a function

data modify storage std:zzz/selectors/funcs/tellraw args set value {}
data modify storage std:zzz/selectors/funcs/tellraw args.target set value "@s"
data modify storage std:zzz/selectors/funcs/tellraw args.message set value "{\"text\": \"Hello, world!\"}"

function std:zzz/selectors/funcs/tellraw with storage std:zzz/selectors/funcs/tellraw args

# On the receiving end, in the tellraw function

# This won't be how it is always done, some functions use the data locations instead of macros.
$tellraw $(target) $(message)
```

Essentially, it boils down to setting up all the given arguments in a map.
These then get decoded on the receiving end, and it's all fine and nice.

## Arrays

This simple expression:

```dps
let array = ["a", b, "c", d, 1.3, 7, 5.6f, true];
```

Would compile down to this:

```mcfunction
data modify storage example:zzz/docs/funcs/array_example locals.array0 set value []
data modify storage example:zzz/docs/funcs/array_example locals.array0 append value "a"
data modify storage example:zzz/docs/funcs/array_example locals.array0 append from storage example:zzz/docs/funcs/array_example locals.b0
data modify storage example:zzz/docs/funcs/array_example locals.array0 append value "c"
data modify storage example:zzz/docs/funcs/array_example locals.array0 append from storage example:zzz/docs/funcs/array_example locals.d0
data modify storage example:zzz/docs/funcs/array_example locals.array0 append value 1.3
data modify storage example:zzz/docs/funcs/array_example locals.array0 append value 7
data modify storage example:zzz/docs/funcs/array_example locals.array0 append value 5.6f
data modify storage example:zzz/docs/funcs/array_example locals.array0 append value true
```

It's quite verbose. The reason for this is that DPScript needs to make sure everything gets appended in the right order,
so inlining some values really isn't possible. Minecraft also doesn't support merging arrays in the way we need to (as far
as we know), so bulk-appending isn't possible.

## Blocks

`init` and `tick` blocks work in the same way as functions, but don't accept any arguments.
